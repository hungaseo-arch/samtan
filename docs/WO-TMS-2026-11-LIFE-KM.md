## 0. 요약

수명 DB의 «주행 KM»이 실제보다 **평균 약 40% 짧게** 나온다. 마모 폐기(WO) 17본 기준으로
현재 평균은 **34,415 km**, 실제는 **57,121 km**이다(§4 수용 기준 표). 고객은 타이어 성능에 만족하는데
TMS 수치가 너무 낮아 분석과 보고에 쓸 수 없는 상태다.

원인은 세 겹이다.

| # | 원인 | 위치 |
|---|---|---|
| C-1 | 최초 장착분(seq 0)은 `mounted_at = NULL` 이라 원장 구간이 전부 `NO_KM` → 거리 0으로 취급 | `v_tire_ledger` (`20261016150000_v_tire_ledger_interpolate.sql`) |
| C-2 | 원장에 쓸 구간이 없으면 `lifeCalc` 가 «측정 점열 최신 − 최초»로 폴백하는데, 이 점열은 **트레드 0 회차를 제외**한 뒤의 것이라, **트레드 최소값이 0이 되기 직전 회차에서 거리가 멈춘다** | `src/data/tmsUtils.ts` `lifeCalc()` ②·④ (`.filter(p => p.tread > 0)` → `spanKm`) |
| C-3 | 폴백 거리는 마지막 점검 회차에서 끝나고 탈착일까지 가지 않는다. 여러 차량을 돈 시리얼은 seq 0 구간이 통째로 빠지고 이후 구간만 합산된다 | 같은 곳 |

**재현 (C-2):** DA1BFBPH02687D(CH 834 L2 Out). 04-02 708,667.8 km(22.0 mm) → 07-05 738,366.2 km(최소 3.82 mm)
→ 07-26 747,052.7 km(최소 **0**) … 09-05 탈착 764,018.9 km.
수명 DB 값 **29,698 km** = 738,366.2 − 708,667.8 (최소 트레드 > 0 인 마지막 회차). 실제는 **55,351.1 km**.
WO 19본 중 11본의 수명 DB 값이 이 계산과 소수점까지 일치한다.

**C-1이 «구조적 하한값»이 아닌 근거:** 폐기된 seq 0 타이어는 전부 **첫 측정 트레드 4점이 22.0 mm(신품)**이다.
첫 점검 시점에 신품이었으므로 그 회차 km를 장착 km로 써도 빠지는 주행은 사실상 없다(장착~첫 점검 사이 0 mm 마모).
decisions **L-4**(«seq 0 NO_KM 은 장착 전 주행을 원래 모르는 구조적 하한값»)는 이 경우에는 맞지 않는다.

## 1. 엔지니어링 기준 (사용자 확정 — 구현 전제)

1. **3 mm(`tread_critical`)는 «권장 교체» 기준이다. «즉시교체»가 아니다.**
2. **수명 종료 = 숄더 완전 마모 또는 센터 카카스 노출.** 센터 홈 깊이 0 mm(숄더 고무 잔존)는 수명 종료가 아니다.
   → 트레드 최소값 0 회차도 **주행 중인 회차**다. 거리 계산에서 빼면 안 된다.
3. 실측 기준 플릿 패턴: 구동축은 센터 마모가 주(S/C 중앙값 0.75), 조향축은 숄더 마모(1.16).
   폐기 시점에 센터 0 · 숄더 3~6 mm가 일반적이다.

## 2. Task

### T-1 (DB) · 최초 장착분 시작점 추론 — `v_tire_ledger`

새 마이그레이션 `supabase/migrations/2026110xxxxxxx_v_tire_ledger_first_mount.sql`.

- 대상: `mounted_at IS NULL`(seq 0) 구간.
- 규칙: 그 시리얼이 **같은 ch·pos 에서 처음 측정된 회차**를 찾는다(`v_tread_series` 또는 `inspections.serial`).
  그 회차의 `tread_avg >= tire_config.new_tread`(신품 확인)이면
  - 시작 경계일 = 그 회차 일자, `km_start` = 그 회차 차량 km(`rnd`와 같은 규칙: 같은 날 최대값, 0 이하는 미측정), `hm_start` 동일
  - `km_method = 'FIRST_NEW_INSPECTION'`, 끝 경계는 기존 규칙(REPLACEMENT → INSPECTION → INTERPOLATED → PREV_ROUND)
  - `km_flag` 는 기존 판정식을 그대로 탄다(→ 보통 `OK`)
- 첫 측정 트레드가 신품 미만이면 **지금처럼 `NO_KM` 유지**(진짜 하한값).
- `mounted_at` 컬럼 값은 **바꾸지 않는다**(덮어쓰기 금지, `v_tco_unit` 이 직접 읽음).
  컬럼은 맨 뒤에만 추가: `mounted_at_effective date`(추론 시작일, 추론 아니면 `mounted_at`), `start_inferred boolean`.
- `v_tire_ledger_total` 은 본문 변경 없이 자동 반영돼야 한다. `invalid_segments` 감소 확인.
- `comment on column` 으로 `FIRST_NEW_INSPECTION` 정의를 남긴다.
- 영향 뷰(자동 반영 확인만): `v_tco_unit` · `v_tco_fleet` · `v_removal_analysis.cumulative_km` · 개체 원장 표.
- 참고: `lifetimes.install_date`는 seq 0이 전부 `2026-04-01`로 들어가 있는데, CH 835의 첫 회차가 04-21이라
  자리채움 값으로 보인다. 시작점으로 쓰지 말 것(앞 회차가 없어 다시 `NO_KM`이 된다).

### T-2 (Web) · 주행 거리와 마모 점열 분리 — `lifeCalc()`

`src/data/tmsUtils.ts`

- **거리는 트레드 값과 무관하게 잰다.** 지금은 ②에서 `tread > 0` 필터를 통과한 점으로 `spanKm` 을 낸다.
  거리용 점열(km 있는 모든 회차)과 회귀용 점열(아래)을 분리한다.
- 폴백 경로(원장 OK 구간 없음)의 거리도 끝을 **원장 `km_end`(탈착 경계)**까지 확장한다. 장착 중이면 마지막 회차.
- 원장 구간이 `FIRST_NEW_INSPECTION` 으로 OK 가 되면 `kmIsLowerBound = false` 가 돼야 한다(현재 식 유지로 자동 충족되는지 확인).
- 구간 원점 `kmOrigin`: `g.mountedAt` 이 null 이어도 `g.kmStart` 가 있으면 그것을 쓴다(지금은 `measurable && g.mountedAt` 조건 때문에 무시됨).
- `LedgerSegment` 타입·`loadData.ts` 매핑에 `kmMethod: 'FIRST_NEW_INSPECTION'`, `mountedAtEffective`, `startInferred` 추가.
- 회귀 점열: 최소 트레드 0 회차를 무조건 버리지 말고, **평균 트레드(`treadAvg`)** 기준으로 단조 마모 필터를 적용한다
  (최소 0이어도 평균은 계속 줄어든다 — 위 재현 예 07-26 2.66 → 08-23 1.93 mm).

### T-3 (Web + DB) · 예상 수명 종료 기준 = 4점 0 mm 또는 3점 0 mm (쎄오님 결정 2026-11-04)

> 최초안(숄더 L·R 평균 0 mm)은 쎄오님 결정으로 대체. 수명 종료 = 트레드 4점 중 **4점 모두 0 mm** 또는 **3점 0 mm** 도달 시.
> 두 기준 중 기본값은 비교표를 보고 쎄오님이 정함 → 구현은 두 기준 모두 산출.

- `tire_config` 에 `life_end_basis text not null default 'min'` 추가(`'min' | 'three_zero' | 'four_zero'`), 관리 › 설정에 노출.
  기본값은 비교 보고 후 쎄오님 결정으로 바꿈(그 전까지 현행 `'min'` 유지 — 화면 수치가 승인 없이 바뀌지 않게).
- `'four_zero'`: 회차별 4점(L·C1·C2·R) 중 **최대값** 점열 → 회귀로 0 mm 도달 km/HM 외삽.
  `'three_zero'`: 회차별 4점 중 **두 번째로 큰 값** 점열(= 3점이 0 이 되는 시점) → 회귀로 0 mm 도달 km/HM 외삽.
  `'min'`: 현재 동작(최소 트레드 0 mm).
- 4점 측정이 있는 회차만 사용. 4점 회차가 2개 미만이면 해당 기준 예상값은 비우고 «4점 측정 부족» 표시. OUTLIER 점은 제외 후 순위 산정.
- 결과 보고에 17본 + 장착 중 전 본의 `min` / `three_zero` / `four_zero` 예상 KM 비교표를 넣는다(기본값 결정 자료).
- 수명 DB 열 머리와 각주 문구를 기준에 맞게 바꾼다(ko/id/en). 예상 CPK도 같은 기준을 쓴다.
- 발주 예상일(`projectReplacement`, `tread_order` 기준)은 **이번 범위가 아니다** — 바꾸지 말 것.
- ~~`replacements.carcass_exposed` 추가~~ — **하지 않음** (쎄오님 결정 2026-11-04 M-2 : 카카스 노출은 폐기 사유로 기록되므로 별도 입력 불필요). 판정 근거는 기존 `removal_code`.

## 6. 사용자 확인 결과 (2026-11-04 쎄오님)

- **M-1** 신품 판정 : 회신 없음 → WO 원안 `tread_avg >= new_tread`(22.0) 로 구현, 결과 보고에 21.5 허용 시 달라지는 본수 병기.
